# Rights and candidate-source decision

**Bead:** `brain-atlas-yum.14.1`
**Verified:** 2026-09-06
**Pins:** siibra `1.0.1a20` / `44549ae595533054135a4d62d567069353027b34`; configurations `177023a506eceff008a012bb0a98d7bca0d1bbd5`
**Scope:** Research decision, not legal advice or implementation approval.

## Decision

1. **Adopt Jülich-Brain v3.0.3 157-area bilateral probability maps as research inputs under CC BY-NC-SA 4.0.** Complete 314-volume acquisition and hashes are in [`probability-manifest.json`](probability-manifest.json). Any derived/distributed artifact must preserve attribution, change notice, NonCommercial, ShareAlike, and no-additional-restrictions conditions; publication design must confirm those conditions fit its distribution model.
2. **Do not claim or rely on Apache-2.0 for `siibra-configurations`.** Pinned configuration archive contains copyright notice but no LICENSE/COPYING/NOTICE/terms file. GitHub repository metadata reports `license: null`. Nature Methods calls software and content “openly accessible” and describes cloning configuration for offline use, but gives no configuration-content reuse grant. Apache-2.0 is verified only for separate `siibra-python` work.
3. **Use configuration NIfTI provider entries as pinned acquisition facts, not as a redistributable licensed hierarchy.** Manifest records exact URLs and map-index correspondence needed to reproduce acquisition. Do not redistribute configuration archive or copy its authored hierarchy/descriptions into product artifacts unless rights are separately established.
4. **Use official licensed dataset files where configuration-content rights would otherwise block progress.** Jülich dataset bucket supplies CC BY-NC-SA 4.0 license, flat 157-structure MPM XML terminology, and a hierarchy JSON. XML supplies all 157 bilateral map names and gray values; 152 names exactly match configured area text and five explicit name correspondences are recorded. Hierarchy JSON is source-pinned but has 155 leaf occurrences and 151 unique leaf names, so it is not a complete 157-area hierarchy. Adopt flat XML/map correspondence now; defer unsupported hierarchy edges rather than treating all work as blocked.
5. **ARCHI terms resolve to CC BY-NC-SA 4.0; still reject candidate on provenance conflicts.** EBRAINS DatasetVersion `f58e4425-6614-4ad9-ac26-5e946b1296cb` supplies DOI `10.25493/ENJ7-ZKM`, license, 78-subject description, 100 maps, and MNI ICBM152 identity. Retained descriptor instead reports 79 subjects and `MNI152_T1_2mm`; pinned configuration claims 78 subjects and 2009c while retrieved NIfTI geometry is 1 mm. Rights no longer block ARCHI, but unresolved source/transform contradiction does.
6. **Reject VEP candidate for adoption now.** Pinned repository has no license file; “kindly provided” is provenance, not permission. Unknown rights are sufficient rejection reason and do not block adopted Jülich work.
7. **HCP DatasetVersion discrepancy is resolved as version skew, not two unrelated datasets.** EBRAINS identifies `6a7e07ad-303c-4b1d-b444-ded9ee782225` as v1.0 (DOI `10.25493/WKH2-GRJ`) and `609c0598-bf02-4b65-8d7d-3a40f0c2f543` as v1.1 (DOI `10.25493/MK9H-ZE1`) of the same HCP short-fiber atlas. Both are CC BY-NC 4.0; v1.1 says it adds affine spatial-coordinate transformations to standard ICBM152. Pinned parcellation/map-level metadata remains on v1.0 while all 673 configured volumes use v1.1, so future adoption must normalize metadata to v1.1 rather than preserve the mixed record. This candidate remains non-adopted here and must not be equated with project HCP-1065 tractography.

## Residual blockers

- Configuration-authored full hierarchy reuse remains unlicensed. Licensed XML supports flat 157-area identity/map correspondence; licensed hierarchy JSON does not cover all 157 unique terms. Full hierarchy adoption needs an explicit grant or another complete licensed ontology source.
- HCP IDs are resolved as v1.0 → v1.1, but pinned configuration mixes v1.0 map/parcellation metadata with v1.1 volumes. Any future candidate adoption must bind v1.1 consistently and validate cohort/registration lineage against project needs.
- ARCHI terms are resolved, but subject-count, template, and resolution conflicts keep it rejected. VEP terms remain unknown and VEP stays rejected.
- CC NonCommercial/ShareAlike compatibility must be reviewed before distributing any Jülich-derived browser artifact. Raw maps remain outside Git.
